# 第三阶段功能模块设计（v1）

## 1. 模块划分

| 模块 | 作用 | 输入 | 输出 |
| --- | --- | --- | --- |
| `config` | 统一管理路径与参数 | 环境与默认值 | 配置对象 |
| `database` | 初始化数据库与连接 | SQL schema | SQLite 连接 |
| `repository` | 封装 CRUD | 业务对象 | 查询结果 / 写入结果 |
| `offline_pipeline` | 离线导入与聚合 | P1 CSV 数据 | DB 中间结果 |
| `service` | 在线推荐与反馈 | seed、top_n | 推荐列表 |
| `benchmark` | 性能评估 | 数据库与样本 | CSV/MD 指标 |

## 2. 核心接口

### 2.1 数据库初始化

- 职责：创建表、索引、唯一约束。
- 目标：重复运行时可幂等执行。

### 2.2 离线导入

- 职责：读取 P1 的 token 化结果和 seed 结果。
- 产物：`keyword`、`intermediary_keyword`、`competition_result`、`search_log`。

### 2.3 在线推荐

- 职责：接收 seed，返回 Top-N。
- 规则：先缓存，后查询，再排序；如果无结果，返回空列表。

### 2.4 反馈写入

- 职责：保存用户评分与备注。
- 价值：形成后续改进依据。

## 3. 异常处理设计

| 异常 | 处理方式 |
| --- | --- |
| 空输入 | 直接返回错误提示，不进入查询链路 |
| seed 不存在 | 返回空结果并记录日志 |
| 数据库失败 | 回滚事务并抛出明确异常 |
| 文件缺失 | 在离线导入阶段提前报错 |

## 4. 性能优化点

1. **批量写入**：比逐条写入更适合离线导入。
2. **索引查询**：降低 seed→结果 的检索成本。
3. **缓存复用**：对热点关键词直接返回内存结果。
4. **预计算排序**：把排序成本从在线阶段移走。

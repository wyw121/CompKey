# P1 思考题（草稿版，可直接再完善提交）

## 1. 大数据量下如何用最简单搜索算法提高效率

1. **分块读取（Chunk）**：避免一次性加载全部文件到内存，按行流式扫描。
2. **先过滤再处理**：先按种子词做快速包含判断，再对命中行做分词与统计。
3. **去重策略前置**：在清洗阶段用 `(user_id, query)` 去重，减少后续计算量。
4. **中间结果落盘**：`cleaned_queries` 与 `seed_related_queries` 分阶段保存，避免重复计算。
5. **样本先验 + 全量执行**：先用样本验证流程，再跑全量，减少返工成本。

## 2. 数据读取和写出编码问题与解决

1. 本实验中原始数据在默认读取下出现乱码，说明编码与终端/编辑器默认设置不一致。
2. 采用编码探测对比：`utf-8`、`gb18030`、`utf-16`，以“可读率”作为判据。
3. 实验结果显示 `gb18030` 可读率最高（1.0000），因此固定读取编码为 `gb18030`。
4. 为兼容后续工具链，清洗与统计输出统一保存为 `UTF-8-SIG`。

## 3. 分词方法比较与有效性提升思考

1. **词典分词（如 jieba）**：速度快、工程落地简单，但对新词和领域词敏感。
2. **规则分词（正则）**：实现成本低，可控性强，但语义边界较弱。
3. **统计/模型分词**：效果通常更好，但实现与维护复杂度更高。

### 提升有效性的方案

- 增加领域词典（广告、商品、品牌词）
- 停用词过滤与词性过滤
- 同义词归一（如“笔记本电脑/笔记本”）
- 对高频噪声词做黑名单清洗

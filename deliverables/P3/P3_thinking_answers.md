# 第三阶段思考题参考答案（v1）

## 1. 该推荐系统的应用场景和服务目标

### 1.1 应用场景

1. **关键词广告投放**：帮助广告主判断某个词的竞争强度。
2. **电商选词**：为商品标题、站内搜索和推广词选择提供参考。
3. **运营分析**：识别高竞争词和长尾词，优化投放策略。

### 1.2 服务目标

- 快速返回竞争性关键词推荐结果。
- 将离线计算结果标准化存库，便于复用。
- 通过日志和反馈形成可持续优化闭环。

## 2. 不同推荐系统的优缺点及适用场景

### 2.1 规则型推荐

**优点**：实现简单、解释性强。  
**缺点**：泛化能力有限，难以覆盖复杂场景。  
**适用**：教学演示、早期原型。

### 2.2 协同过滤推荐

**优点**：能利用用户行为挖掘潜在偏好。  
**缺点**：冷启动问题明显，对稀疏数据敏感。  
**适用**：用户行为丰富的平台。

### 2.3 内容推荐

**优点**：与关键词、文本语义天然匹配。  
**缺点**：容易过度依赖已有内容特征。  
**适用**：关键词推荐、文本检索、商品标签。

### 2.4 本项目采用的 CompKey 思路

**优点**：

- 贴近“竞争性关键词”业务语义。
- 结果可解释，便于汇报和验收。
- 适合用离线统计支撑在线检索。

**缺点**：

- 对数据质量和口径依赖较强。
- 对新词和极低频词的处理需要额外策略。

## 3. 系统设计理念

本系统采用“**离线预计算 + 在线快速查询 + 结果可追溯**”的设计理念：

1. 离线阶段把复杂统计提前算好。
2. 在线阶段只查数据库、读缓存、输出结果。
3. 通过日志、反馈和数据库结构保证可维护性。

## 4. 下一步优化方向

1. 增加缓存命中率统计。
2. 引入更精细的权重公式。
3. 将 SQLite 升级为 MySQL/PostgreSQL 以支持并发。
4. 接入 Web API 或轻量网页界面。
5. 引入用户反馈校正推荐分值。
